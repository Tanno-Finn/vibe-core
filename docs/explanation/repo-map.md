# What is where

Open this repository in a file browser and you'll see a couple of dozen folders and files.
That's a lot to face if you didn't build it. This page is the human map: not a technical
inventory, but a plain-language answer to *"what is this, who reads it, and do I ever need to
touch it?"* — so you can ignore most of the tree with a clear conscience and know exactly
where to look when you do want something.

You don't have to read any of these files to use the kit — your agent reads them for you.
This map is for the moments you're curious, or clicking around without an agent open.

## The ten places that actually matter

Everything else is either generated, standard tooling, or config you'll rarely open. These
are the ones worth recognizing.

| Place | What it is (and what it's *for*) | Who reads it | Do you touch it? |
|---|---|---|---|
| [`AGENTS.md`](../../AGENTS.md) | The one-page contract every AI agent reads first — the standards, the safety rules, and pointers to everything else. It's *why* an agent knows how to behave here without being told. | Your agent (and you, if curious) | Rarely — it's deliberately short and stable |
| [`.claude/skills/`](../../.claude/skills/) | The agent's **named jobs** — `onboarding`, `help`, `status`, `new-content`, and more. Each folder is one skill the agent can run when you ask. This is *what the agent can do*. | Your agent | No — you *invoke* them by talking, you don't edit them |
| [`directives/`](../../directives/) | The agent's **playbooks** — how it works: how it commits, how it translates, how it handles many files at once. Guidance, not gates. It's *how the agent works well*, distilled. | Your agent | No, normally |
| [`base/`](../../base/) | The **agent operating system**: the four standards (accessibility, privacy, security, quality), the safety model, the bookkeeping rules. The non-negotiable foundation that doesn't depend on this particular app. | Your agent | No — this is the engine room |
| [`profile/`](../../profile/) | **You, in a file.** After onboarding, `profile/USER-MANIFEST.MD` records your language, goals, and preferences so every agent session starts already knowing how you like to work. | Your agent; it's *about* you | Indirectly — onboarding fills it; you can edit it |
| `src/` | The **actual app** — the Angular code (`src/app/`) and its content and images (`src/assets/`). This is the product itself: the pages, demos, glossary, and timeline people will see. | Your agent; you, to see the content | Yes, eventually — but usually *through* the agent |
| [`docs/`](../) | The **human documentation** you're reading now — tutorials, how-to guides, explanations, in both English and German (`docs/de/`). Written for people, not the machine. | You | Only if you want to improve the docs |
| [`specs/`](../../specs/) | Where **non-trivial work gets shaped** before it's built — one dated folder per idea, so a big change is thought through on paper first. It's the project's *thinking-out-loud* space. | Your agent; you, to follow along | Occasionally, with the agent |
| [`JOURNAL.md`](../../JOURNAL.md) · [`OPEN-QUESTIONS.md`](../../OPEN-QUESTIONS.md) | The **project's books.** The journal is the running diary of what happened each session; open-questions is the short list of decisions the agent is waiting on *you* for. Together they mean you can always see where things stand. | Both — the agent writes, you read (and answer) | Yes — you read the journal, you answer the questions |
| [`packs/`](../../packs/) | **Optional add-on bundles** for a role or workflow — for example a `teacher` pack that adds worksheet and quiz jobs. Off until you turn one on by asking. It's *extra abilities you opt into*. | Your agent, when a pack is active | No — you activate one by talking |

## Things you can safely ignore

If you see these while clicking around, they're not for you — they're generated or standard
plumbing, and nothing here is worth reading or editing by hand:

- **`node_modules/`** — the downloaded libraries the app is built from. Huge, automatic,
  never edited. `npm install` creates it.
- **`dist/`** and **`dist-content/`** — the *built* output of the app. Generated by a build;
  overwritten every time. You deploy this, you don't edit it.
- **`.angular/`**, **`tmp/`**, **`.idea/`** — caches and editor scratch space. Safe to
  ignore entirely.
- **`kit.json`**, **`angular.json`**, **`package.json`**, the `tsconfig*.json` files —
  configuration the agent and the build tools read. Real, but rarely something you open
  yourself.

## "Where do I find…"

The four most common things you'll actually want to change — and the honest answer to each
is usually *"just ask the agent"*, but here's where it lives:

| I want to… | It lives in… | The easy way |
|---|---|---|
| **Change some text** on a page | `src/assets/` (content) or the article/glossary/timeline data | Ask the agent, or run `/new-content` |
| **Change the colors** or look | [`docs/DESIGN-SYSTEM.MD`](../DESIGN-SYSTEM.MD) defines the design tokens; the components use them | Ask the agent — it works from the design system, not scattered CSS |
| **Add a new page** | `src/app/` (the app's routes and components) | Ask the agent, or run `/new-component` / `/new-content` |
| **Change the language**, or add one | Content lives in language folders under `src/assets/`; user-facing docs mirror into `docs/de/`, a pack's docs sit beside the original (`README.de.md`) | Ask the agent — translation has its own careful flow |

Notice the pattern: for anything real, the door is the same — **tell the agent what you
want.** This map exists so that when it tells you *where* it made a change, the place already
means something to you.
